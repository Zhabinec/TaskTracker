Backend-тесты проверяют различие liveness/readiness, скрытие документации в production, timezone и конфигурацию БД. На отдельной PostgreSQL проверены upgrade → downgrade → upgrade, повторный upgrade, отсутствие расхождения ORM и миграции через Alembic check, отказ readiness для более новой схемы, UNIQUE email, конкурентная вставка одного email, rollback после выполненного INSERT, FK и ограничения сессий, timezone-aware timestamps, readiness при неверном пароле и недоступной БД. Таблицы не создаются через `create_all`.

Дополнительные backend-тесты проверяют регистрацию и нормализацию email, Argon2id и хранение только хеша сессии, me, отзыв и истечение сессии, замену текущего токена при входе, атомарность конкурентной регистрации, одинаковые ошибки для неизвестного аккаунта и неверного пароля, общий лимит между workers, глобальный лимит при смене email и Retry-After. Проверены Origin, размер обычного и chunked тела, CSRF от другой сессии и отсутствие пароля в ошибке валидации. Отмена команды после INSERT откатывает транзакцию и освобождает соединение через штатный контекст SQLAlchemy.

Frontend-тесты проверяют серверную конфигурацию, таймаут и запрет кеша/редиректов; HttpOnly / SameSite / Secure / __Host- cookie, отсутствие credentials в публичном JSON, Origin, CSRF (включая не-ASCII ввод), неоднозначные и слишком большие формы, сохранение cookies при ошибке отзыва и их удаление после успешного выхода. Проверен 303 для HTML-форм.

Playwright проверил весь путь регистрации → reload → logout → неверный пароль → login; старый credential после выхода даёт 401. Отдельно проверены чужой/отсутствующий Origin, поддельный logout, ограничение размера тела и публичный JSON без токенов. Мобильная форма шириной 390px не имеет горизонтального скролла, Tab переводит фокус с email на пароль; её скриншот просмотрен. Регистрация и выход работают без JavaScript. Для этого защищённая страница не выдаёт Suspense loading-boundary до завершения проверки сессии.

## Решения по совместимости

- Node.js 24 LTS, Python 3.14; точные зависимости — в lock-файлах.
- TypeScript 5.9.3: совместим с peer dependencies openapi-typescript 7.13.0, Next.js и TypeScript ESLint. Принудительный обход peer dependencies не используется.
- ESLint 10 с официальными плагинами Next.js, React Hooks и TypeScript. Общий `eslint-config-next` заменён явной конфигурацией, поскольку его транзитивные React/import/a11y плагины ограничивали peer dependency до ESLint 9. Правила Next Core Web Vitals и React Hooks включены. Полная проверка доступности остаётся обязательной при реализации интерфейсов.
- Docker-образы Python, Node, uv и PostgreSQL закреплены по проверенным digest; официальные GitHub Actions закреплены по commit SHA.
- На этой машине порт 5432 занят существующей БД, а 55432 попадает в исключённый Windows диапазон. Используется проверенный порт 15432; он настраивается через `POSTGRES_PORT`.

## Границы проверки

Приложение готово к локальному ручному тестированию авторизации. Создание проектов и задач ещё не реализовано; `/projects` показывает текущий аккаунт и выход. Положительная readiness подтверждает доступность и совместимость схемы БД, а не завершённость всего MVP.

Не выполнялись тесты конкуренции ещё не реализованных команд проектов и задач, аудит Python-зависимостей, полный поиск секретов специализированным сканером, backup/restore и публичный деплой. Публичная эксплуатация требует HTTPS и ограничения запросов на proxy/платформе. Восстановление пароля и подтверждение email не реализованы. npm audit не заменяет общий аудит безопасности.

Workflow CI подготовлен, но не запускался на GitHub: репозиторий инициализирован только локально, remote и публикация не настроены. Локальные проверки этого не подменяют.

Проверки выполнялись вне песочницы там, где она блокировала сеть, Docker, создание standalone-файлов или выполнение Python-тестов. После ошибочного захвата кеша первым запуском Ruff кеш исключён из его обхода, Python-окружение пересоздано из lock-файла; результаты выше относятся к чистому окружению.
